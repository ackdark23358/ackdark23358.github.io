해맨다면 카피 인바이트 링크를 주면 ....
admin, read, write권한
권한은 보통 개발자는 write....

저장소의 협업자의 컴퓨터를 세팅하는 방법....

a 디렉토리 는 내가 사용하는 디렉터리
b 디렉터리는 새로운 사람 clone으로 레포지토리를 복제


a는 사람이 작업을 하고 커밋하고 버전을 만들고 푸쉬를 했다면....
b는 풀을 해서 추가한다음 작업해야하는데 깜박한경우
파일을 수동으로 수정..... git commit -m "afsd" ......

왼쪽의 a라는 사람이 최신버전을 올려놨는데
b라는 사람이 pull을 해서 작업하는걸 했어야하는데 하지않게됬거나 중복됬다면....

b에게 git push를 할때 거절을 하게된다... 깃 허브에 작업한게 있느데 그걸하지 않았다고 알려준다.
b가 git pull을 하게되면 같은줄...을 수정해서 에러가 나게된다.
병합도구로 git merge 툴로 수정 ...  변경점을 확인하고 .... 에러메시지 차이점 내용을 지우고 저장 add , commit ... 충돌을 했었다는 것을 깃이 알기때문에 커밋메시지를 추가로 만들어준다. 충돌후 내용을 써주면 커밋이 만들어지게된다. (파일 수정이후)
병합 커밋.... 공통의 조상을 참조해서 병합하고 커밋이이루어지게된다. a, b의 내용이 같게된다. 최대한 빨리하고 커밋을 하고 push를 해야지 충돌이 나지 않는다. 

커밋 풀 푸쉬를 자주하는 것이 좋다. 
원격저장소를 중심으로 협업을 할때는 풀을하고 커밋을하고 푸쉬를 하게된다. 풀이라는 것 대신에 fetch를 하고 git merge , git fetch HEAD를 해서 git push를 한것과 같이 할 수있다.

원격저장소보다 이전에 head가 되있다면 깃 fetch를 하고 merge 해서 병합하거나 pull....
